# ADR-10 — API style

- Status: accepted
- Date: 2026-11-11
- Mode stage: Stage 3

## Context
Frontend (Next.js) consumes backend (FastAPI); need claim upload, extraction review, fraud flags, adjudication, audit, reporting. Team of 4; need fast iteration and auto-generated types.

## Problem
REST vs GraphQL vs gRPC vs tRPC?

## Considered alternatives
1. **REST + OpenAPI (FastAPI auto-docs)** — simple, cacheable, easy file upload (multipart), universal tooling, auto-generated typed client. Con: over/under-fetching possible; mitigated by purpose-built endpoints.
2. **GraphQL** — flexible querying, but adds complexity, file upload awkward, and team less fluent; not justified for MVP.
3. **gRPC** — high performance, but poor browser support (needs proxy) and overkill; not for web frontend.
4. **tRPC** — end-to-end types, but requires TypeScript backend (we chose Python/FastAPI); incompatible.

## Decision
REST over HTTPS with JSON + multipart, versioned under `/api/v1`, with RFC 7807 problem details for errors, OpenAPI generated by FastAPI, and a typed client generated in CI. See api-contracts.md.

## Consequences
- Simple, debuggable, works with any client.
- File upload via multipart natively supported.
- Typed client generation step in CI; keep OpenAPI stable.
- Real-time (SSE/WebSocket) deferred to P1 (polling in MVP).
